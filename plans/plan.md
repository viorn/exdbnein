# exdbnein — консольный установщик Debian

Главный план проекта. Детали по этапам — в `plans/phase1.md` … `plans/phase9.md`.
Сырой анализ рисков и сценариев — [`plans/plan-analysis.md`](plan-analysis.md).

## О проекте

Аналог `archinstall` для Debian: интерактивный TUI-установщик на `bun + TypeScript + @clack/prompts`,
поставляемый внутри собственного LiveCD. Репозиторий содержит и сам установщик, и скрипты сборки LiveCD.

## Зафиксированные решения

| Решение | Значение |
|---|---|
| Архитектура | только `amd64` |
| Файловые системы | приоритет `btrfs` (subvolumes `@`, `@home`, `@snapshots`, `compress=zstd,noatime`), базовый вариант `ext4` |
| LUKS/LVM | пост-MVP |
| Сборка LiveCD | собственный `livecd/build.sh` (debootstrap + squashfs + xorriso/grub-mkrescue), без `live-build` |
| Профили | YAML, статичные (без условий/переменных в MVP), наследование через `extends` |
| Загрузчик | только GRUB в MVP; systemd-boot отложен |
| Разметка по прошивке | BIOS → MBR, UEFI → GPT + ESP |
| Маркер LiveCD | файл `/etc/exdbnein-live` (создаётся сборкой ISO); dev-режим вне LiveCD — флаг `--force` |
| fstab | по UUID, не по именам устройств |
| Снапшоты btrfs | в MVP только subvolumes; snapper/timeshift — пост-MVP |
| Авторежим | `--config` обязателен и должен быть полным; шаги пропускаются через хук `Step.skip` |

## Принципы

- **MVP по шагам.** Каждый этап заканчивается работоспособным состоянием и проверяется в QEMU.
- **Двухфазная модель.** Конфигурация (фаза A) и применение (фаза B) разделены (см. ниже).
- **Идемпотентность и dry-run.** Любой деструктивный шаг сначала показывается пользователю как план команд.
- **Безопасность.** Отказ, если не root, не в LiveCD, или целевой диск — носитель LiveCD.
- **Тонкая обёртка над системой.** Вся работа с дисками/пакетами — через модуль `system/`;
  логика TUI не знает про shell.
- **Конфиг как данные.** Установка описывается сериализуемым `InstallConfig` (JSON) —
  сохранить, загрузить, прогнать автоматически.

## Двухфазная модель (архитектура)

```mermaid
flowchart LR
    subgraph A[Фаза A — конфигурация]
        S1[шаг диск] --> S2[шаг locale]
        S2 --> S3[шаг сеть]
        S3 --> S4[шаг пользователи]
        S4 --> S5[шаг профили]
        S5 --> R[шаг ревью]
    end
    R --> B{подтверждение}
    B --> C[сухой прогон команд]
    C --> subgraph D[Фаза B — применение]
        P1[разметка] --> P2[debootstrap]
        P2 --> P3[настройка chroot]
        P3 --> P4[профили и очистка]
    end
```

- **Фаза A** — шаги визарда только мутируют `InstallConfig` в памяти ([`runWizard`](../src/ui/wizard.ts:29)),
  никаких изменений системы. Допустимо read-only зондирование среды (lsblk, `/sys/firmware/efi`, сеть).
  Back-навигация разрешена **только в этой фазе**.
- **Фаза B** — отдельный install-раннер (модуль `src/install/`), принимает готовый конфиг и выполняет
  системные операции. Не использует TUI-шаги, линеен, без возвратов. Запускается из режима
  `--unattended` и из QEMU-тестов.
- **Граница** — шаг ревью ([`reviewStep`](../src/steps/review.ts:23)): валидация конфига, показ плана,
  подтверждение. Внутри фазы B перед разметкой — отдельный dry-run экран с точным списком команд.
- **Необратимая точка** — разметка и `mkfs`. До неё всё обратимо.

```
│   ├── profiles/        # загрузка/резолв YAML-профилей (наследование)

│   └── utils/
├── profiles/            # встроенные YAML-профили (base, server, desktop, dev)
├── livecd/              # сборка LiveCD (этап 8)
├── plans/               # документация планирования (этот файл и phase*.md)
├── tests/               # bun test
├── scripts/             # qemu-test.sh и пр. (этап 9)
└── package.json
```

## Обзор задач по этапам

Краткие чек-листы верхнего уровня; полные спецификации и риски — в соответствующих `phase*.md`.

### Этап 1 — Ядро TUI и модель конфигурации
Закрыт полностью: авторежим через `Step.skip`, единообразная навигация «назад»,
автосохранение черновика. Подробности — [phase1.md](phase1.md).

### Этап 2 — Профили YAML
Реализован: формат (`packages`, `services`, `commands`, `files`, `extends`), загрузка из `profiles/`
и `--profiles-dir`, резолв наследования с защитой от циклов, валидация, выбор в визарде
с предпросмотром, встроенные профили `base`, `server`, `desktop`, `dev`. Зависимость: `yaml`.
Применение профилей — этап 7. Подробности — [phase2.md](phase2.md).

### Этап 3 — Определение окружения
Реализован: pre-flight (root + маркер `/etc/exdbnein-live`, dev-флаг `--force`),
UEFI/BIOS, список дисков через `lsblk -J` (модуль [`src/system/disks.ts`](../src/system/disks.ts)),
исключение носителя LiveCD и системного диска, проверка сети с таймаутами.
Подробности — [phase3.md](phase3.md).

### Этап 4 — Разметка диска
Авто/ручная/«оставить разделы»; UEFI → GPT+ESP+`/`(+swap), BIOS → MBR;
btrfs subvolumes; parted/sgdisk + mkfs.*; монтирование в `/mnt`; dry-run экран;
защита от повторного wipe при повторном входе.

### Этап 5 — Базовая система
`debootstrap` (stable) с зеркалом, bind-mounts (включая `/sys/firmware/efi/efivars` для UEFI),
`sources.list`, ядро + firmware, `fstab` по UUID.

### Этап 6 — Настройка системы
hostname, locale/keymap/timezone (debconf-пресеты), пользователи и sudo, сеть, GRUB
(BIOS/UEFI), os-prober выключен по умолчанию.

### Этап 7 — Пост-установка
Применение профилей (пакеты, сервисы, команды в chroot, файлы с префиксом целевого корня),
хуки, очистка, размонтирование и reboot; стратегия ошибок вместо rollback.

### Этап 8 — LiveCD
`build.sh`: live-система + скомпилированный бинарь установщика (`bun build --compile`),
squashfs, гибридный ISO BIOS+UEFI, автозапуск на tty1, маркер `/etc/exdbnein-live`.

### Этап 9 — Тестирование
Юнит-тесты (lsblk, fstab, профили, имена разделов), прогоны в QEMU BIOS+UEFI по
`--unattended` конфигу, `scripts/qemu-test.sh`, документация.
