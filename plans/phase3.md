# Этап 3 — Определение окружения

Статус: ⬜ не начат.
Источник анализа: [`plans/plan-analysis.md`](plan-analysis.md), раздел «Этап 3».

## Цель

Read-only зондирование среды (фаза A): понять, где мы запущены, что за железо и сеть,
и предоставить безопасный список целевых дисков.

## Задачи

- [ ] Проверка root (`uid === 0`)
- [ ] Проверка LiveCD-маркера `/etc/exdbnein-live` (P3.1)
- [ ] Dev-режим: флаг `--force` (или env `EXDBNEIN_DEV=1`) для запуска вне LiveCD (P3.1)
- [ ] Определение прошивки: UEFI vs BIOS (`/sys/firmware/efi` существует)
- [ ] Список дисков через `lsblk -J -o NAME,PATH,SIZE,TYPE,RM,TRAN` с моделью/размером/типом/съёмностью
- [ ] Канонизация путей дисков: by-id/by-path, `pN`-суффиксы для NVMe/MMC (P3.2)
- [ ] Исключение носителя LiveCD из списка целевых дисков (P3.3)
- [ ] Проверка сети: интерфейсы, DHCP, доступность зеркала Debian с таймаутами (P3.4)

## Принятые решения

- Маркер LiveCD: файл `/etc/exdbnein-live`, создаётся сборкой ISO (этап 8).
- Dev-режим — единственный способ запустить установщик на хосте разработчика;
  в dev-режиме целевые диски помечаются и используются только с дополнительным подтверждением.

## Риски

- P3.1 🔴 Маркер надо определить заранее + нужен `--force`, иначе этапы 4+ нетестируемы вне LiveCD/QEMU.
- P3.2 🟡 Канонизация путей `lsblk`: `/dev/disk/by-id/…`, `/dev/nvme0n1p1`, `/dev/mmcblk0p1` —
  единый модуль `src/system/disks.ts` с тестами (используется на этапе 4).
- P3.3 🔴 Исключение носителя LiveCD: учитывать squashfs из памяти, `overlay`, `/dev/mapper`,
  загрузку с CD; проверять совпадение по mountpoint и DEVNAME, а не только по имени.
- P3.4 🟡 Сеть: таймауты и повтор при недоступном зеркале; спиннер вместо зависшего TUI;
  при неудаче — предложить другое зеркало или продолжить без проверки.

## Критерии готовности

- `exdbnein` отказывается запускаться без root и без маркера (если не `--force`).
- UEFI/BIOS определяется корректно; выбор диска невозможен для носителя LiveCD.
- Имена разделов (`nvme0n1p1` vs `sda1`) генерируются правильно — покрыто тестами.
- Проверка сети завершается за конечное время при любом ответе сети.
- `bun run check` зелёный.
