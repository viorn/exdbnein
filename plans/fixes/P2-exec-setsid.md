## Проблема

`exec()` запускает команды через `Bun.spawn(command)` **без** `setsid`.
При Ctrl+C сигнал доходит только до установщика, но не до дочерних процессов
(parted, mkfs, mount) — они остаются сиротами и продолжают работу.

`runLong()` в [`src/system/run.ts:59`](../src/system/run.ts:59) уже делает правильно:
`Bun.spawn(["setsid", ...command])` + `process.kill(-groupPid, ...)` в обработчике SIGINT.

## Воспроизведение

1. `prepareDiskStage` начал разметку/форматирование (`runCommands`, [`src/install/disk.ts:39`](../src/install/disk.ts:39)).
2. Нажать Ctrl+C.
3. Установщик завершается, но `mkfs.btrfs`/`parted` продолжают работать как сироты,
   оставляя устройство занятым и/или незавершённую операцию на диске.

## Текущее состояние (актуализация 2026-10-02)

- `runLong` существует и используется для долгих операций (debootstrap/apt).
- Дисковая стадия всё ещё гоняет команды через обычный `exec` —
  секция «Рекомендуемое исправление» ревью не выполнена.
- Также plain `exec` используется для служебных коротких команд (lsblk, findmnt,
  blkid) — для них process-group isolation не критична, но единый механизм упростит
  поддержку.

## Рекомендуемое исправление

**Вариант A (минимальный):** перевести `runCommands` в [`src/install/disk.ts:39`](../src/install/disk.ts:39)
на `runLong` (у него уже есть spinner, timeout и kill-group). Команды короткие —
spinner просто покажется кратко.

**Вариант B (последовательный):** добавить опцию `setsid?: boolean` в `ExecOptions`
и использовать `["setsid", ...command]` там, где команда может оставить потомков
(partition/format/mount), сохраняя быстрый путь для служебных вызовов.

Рекомендуется **Вариант A**: меньше кода, единый механизм прерывания для всех фаз
установки, а не только долгих.

## Критерии приёмки

- [ ] Ctrl+C во время `prepareDiskStage` не оставляет работающих потомков
      (`pgrep -f 'parted|mkfs'` пуст после выхода).
- [ ] То же для других стадий Phase B (apt/debootstrap — уже через `runLong`).
- [ ] Юнит-тесты `exec`/`runLong` не сломаны (`bun run check`).
- [ ] Ручная проверка: повторный запуск сразу после Ctrl+C не упирается в
      заблокированное устройство/монтирование.
