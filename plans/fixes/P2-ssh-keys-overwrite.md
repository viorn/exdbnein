## Проблема

`planUserSsh` сравнивает и **перезаписывает** `authorized_keys` целиком:

```ts
const current = await Bun.file(`${TARGET_ROOT}${sshDir}/authorized_keys`)
  .text()
  .catch(() => "");
if (current === keys) return [];
return [
  { description: `Write ${sshDir}/authorized_keys`, file: { ... } },
  ...
];
```

При нескольких `UserConfig` для одного пользователя или при повторном запуске
с новыми ключами старые ключи теряются (поведение «полный список» не задокументировано).

## Текущее состояние (актуализация 2026-10-02)

Логика не менялась: по-прежнему `current === keys → skip`, иначе полная запись.
Рекомендация ревью («документировать, что `sshKeys` — это полный список,
а не дополнение») не выполнена.

## Рекомендуемое исправление

1. **Зафиксировать контракт.** В [`src/config/types.ts:40`](../src/config/types.ts:40)
   задокументировать: `sshKeys` — **полный** желаемый набор ключей пользователя;
   файл приводится к этому набору (идемпотентно), существующие ключи вне списка удаляются.

2. **Или** изменить поведение на аддитивное:
   - читать текущий `authorized_keys`,
   - добавлять только новые ключи из `sshKeys` (по уникальности),
   - не трогать существующие.

Выбор поведения — продуктовое решение. Рекомендация: **оставить полную замену**,
но явно задокументировать и добавить предупреждение в интерфейс шага Users,
если в списке уже есть пользователи/ключи.

3. Учесть кейс «несколько UserConfig с одним username» — сейчас валидатор шага
   ([`src/steps/users.ts:22`](../src/steps/users.ts:22)) запрещает дубликаты,
   но при загрузке конфига дубликаты возможны — добавить проверку в валидатор конфига
   ([`src/config/validate.ts`](../src/config/validate.ts)).

## Критерии приёмки

- [ ] Контракт `sshKeys` задокументирован в типах (комментарий над полем).
- [ ] Если выбрано аддитивное поведение: повторный запуск с новым ключом сохраняет
      старые ключи; юнит-тест на merge.
- [ ] Если остаётся полная замена: юнит-тест, подтверждающий перезапись
      (существующий ключ вне списка удаляется).
- [ ] Валидатор конфига отклоняет дубликаты username.
- [ ] `bun run check` проходит.
