# Этап 7 — Пост-установка и завершение

Статус: ✅ завершён.
Источник анализа: [`plans/plan-analysis.md`](plan-analysis.md), раздел «Этап 7».

## Цель

Фаза B: применить выбранные профили в установленную систему, выполнить хуки, очистить временные
файлы, размонтировать диск и предложить перезагрузку.

## Задачи

- [x] Применение профилей: установка пакетов, включение сервисов, `commands`, `files`
- [x] Чёткое разделение «пространств путей»: файлы пишутся с префиксом целевого корня
      (`/mnt/etc/...`), команды выполняются в chroot (P7.1)
- [x] Хуки/скрипты пользователя после установки — через `commands`/`files` профилей
      (произвольный shell в chroot, `optional` не прерывает установку)
- [x] Очистка: `apt clean`, удаление временных файлов
- [x] Размонтирование, `swapoff`, финальный экран, `reboot` (в `finally`-блоках, P7.3)
- [x] Стратегия ошибок: понятный отчёт + повторный запуск поверх готовой разметки (P7.2)

## Принятые решения

- **Rollback не предусмотрен** (данные уже стёрты — нечего откатывать). Вместо него:
  лог шагов в `/var/log/exdbnein/install.log` (на LiveCD-носителе и внутри целевой системы)
  и идемпотентный повторный вход — установщик распознаёт уже размеченный диск
  (`isDiskPrepared`) и продолжает с места ошибки.
- `files` из профилей — это пути целевой системы; writer добавляет префикс корня монтирования
  (`profileTargetPath`: `/etc/x` → `/mnt/etc/x`). `commands` — выполняются через chroot и видят
  корень целевой системы напрямую (`inChroot(["sh", "-c", cmd])`). Это требование фиксируется
  в схеме профиля и в коде (P7.1).
- Размонтирование `/mnt` и `swapoff` выполняются всегда — даже при ошибке (`finally` в
  [`runInstall`](../src/install/index.ts)).

## Реализация

### Стадии фазы B

- [`postInstallStage`](../src/install/postinstall.ts) — новый шаг после настройки системы:
  загружает профили из `profilesDir` (`--profiles-dir`), резолвит наследование и строит
  идемпотентный план: пакеты → сервисы → файлы → команды → очистка. Как и остальные стадии —
  dry-run план с подтверждением в интерактиве.
- [`finishInstall`](../src/install/finish.ts) — финальный экран со сводкой
  ([`summaryText`](../src/install/finish.ts)), размонтирование, `swapoff` и `reboot` по выбору
  (в авторежиме перезагрузка не выполняется).

### Применение профилей ([`src/system/postinstall.ts`](../src/system/postinstall.ts))

| Что | Как | Идемпотентность |
|---|---|---|
| Пакеты | один `apt-get install --no-install-recommends` недостающих | `dpkg-query` статус каждого пакета |
| Сервисы | один `systemctl enable` в chroot | `systemctl is-enabled` |
| Файлы | writer с префиксом `TARGET_ROOT` (P7.1) | сравнение содержимого, совпавшее — пропускается |
| Команды | `chroot /mnt sh -c "<cmd>"` (P7.1) | маркер `/var/lib/exdbnein/applied.json` внутри целевой системы |
| Очистка | `apt-get clean` + `rm -rf /mnt/tmp/exdbnein-*` | — |

- **Команды:** маркер применённых команд хранится в целевом корне и переживает перезагрузки —
  повторный запуск не дублирует выполнение. Успешная команда помечается сразу после выполнения;
  упавшая `optional` — нет (будет повторена).
- **Optional-команды** (поле `optional: true` в профиле): ошибка не прерывает установку,
  выводится предупреждение, выполнение продолжается.
- **Порядок:** пакеты ставятся до включения сервисов (нужны unit-файлы), файлы — до команд.

### Лог и ошибки (P7.2)

- [`InstallLogger`](../src/system/log.ts) собирает шаги в памяти и дописывает их best-effort
  в два файла: `/mnt/var/log/exdbnein/install.log` (в установленной системе) и
  `/var/log/exdbnein/install.log` (на LiveCD-носителе).
- Перед размонтированием лог сбрасывается в целевой корень, при ошибке — после teardown
  в хостовый лог. При любой ошибке остаётся читаемый отчёт и корректно размонтированный диск.

### Финализация (P7.3)

- [`unmountTarget`](../src/system/finalize.ts) — порядок обратный монтированию: ESP, btrfs
  subvolumes (`@home`, `@snapshots`), псевдо-ФС (`/dev/pts`, `/dev`, `/proc`, `/sys`, `/run`),
  затем `/mnt`. Каждая точка проверяется через `findmnt` — повторный вызов безопасен.
- [`swapoffTarget`](../src/system/finalize.ts) — отключает только swap целевого диска
  (по префиксу устройства + явный раздел для схемы `keep`), swap LiveCD не трогает.
- Teardown вызывается из `finally` в [`runInstall`](../src/install/index.ts) — работает и в
  unhappy-path.

## Риски

- P7.1 🔴 Два разных «пространства путей» (writer vs chroot runner) — разделены в коде:
  `profileTargetPath` для файлов, `inChroot(["sh", "-c", ...])` для команд.
- P7.2 🔴 Нет rollback — стратегия «отчёт + повторный запуск»: журнал установки, маркер
  применённых команд, идемпотентные планы всех стадий (диск — `isDiskPrepared`,
  база — `isBaseInstalled`, пакеты — dpkg-статусы, сервисы — `is-enabled`, файлы — содержимое).
- P7.3 🟡 Очистка при ошибке — размонтирование и swapoff в `finally`, а не в happy-path.
